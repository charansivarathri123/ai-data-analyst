Layer-by-Layer Architectural Role
1. Frontend Application (Next.js + Tailwind + Motion)
File Ingestion: Drag-and-drop zone using react-dropzone with chunked upload direct to S3/Supabase storage.
Agent Execution Terminal: Displays a real-time terminal or step-progress bar powered by Server-Sent Events (SSE) streaming from FastAPI (event: agent_step, data: "Running outlier detection...").
Interactive Results: Displays key metrics, correlation heatmaps, and downloadable assets (clean_data.csv, report_template.pbip).
2. Analytical Engine (DuckDB + Polars)
Replaces standard Pandas. DuckDB allows agents to execute direct SQL queries against uploaded CSV/Parquet files without loading the entire dataset into RAM.
Polars runs high-speed vectorized transformations, automated null imputations, and schema casting.
3. Multi-Agent Engine (LangGraph + E2B Sandbox)
State Machine: LangGraph stores the pipeline state (raw_data_path, clean_data_path, eda_metrics, root_causes, dax_measures).
Self-Healing Execution: When the Data Cleaner Agent generates Python code to clean anomalous values, it runs the code inside an E2B Sandbox. If the script throws a traceback, the agent catches the error, reflects, and fixes the script automatically.
4. Power BI Programmatic Pipeline (PBIP / TMDL)
Modern Power BI Desktop uses PBIP format, where data models are defined using TMDL (.tmdl files) and report visuals use JSON.
The BI Agent emits:
A star-schema TMDL script defining tables, data types, relationships, and DAX measures.
A zipped folder bundle containing the .pbip files.
Users can open the generated .pbip directly in Power BI Desktop with zero manual modeling.
